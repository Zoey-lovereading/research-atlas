# 研究图谱 · Research Atlas

从一组互补综述出发，整理领域分类、证据可追溯的研究进展，以及你自己的研究计划。

## 开始使用

下载项目文件，保留原有目录结构，用浏览器打开 `index.html`。无需安装依赖。首次打开会加载一个虚构的城市热岛研究示例，用于演示数据结构和界面操作。开始自己的研究时，建立空白项目或导入已有的项目 JSON。

1. **选取约 5 篇互补综述。** 先定研究对象、时间范围和纳入边界。用总览综述搭框架，再选聚焦不同问题、方法或应用场景的综述。在「文献与分类」打开「管理文献」，登记年份、作者、DOI 链接或出版页面，并记下每篇文献的范围。需要追溯某项发现时，也可在这里录入原始研究论文。
2. **从综述目录和正文提取分类。** 在「编辑项目 → 分类证据 → 按目录导入」选择来源文献，粘贴 Markdown 标题或数字编号目录，生成分层分类并保留章节路径。校对分类边界，合并同义主题。同一篇文献可以关联多个分类，同一分类也可以关联多篇文献。
3. **按分类整理证据。** 在编辑器的「分类证据」中填写来源文献的原文章节、图表编号或页码，以及该处讨论的**机制、观测方法、研究结果**。机制记录解释了什么，观测方法记录如何测量与比较，研究结果记录证据及其适用条件。每条映射保留自己的出处。通过「分类证据」面板按分类筛选，对照综述与原始研究的结论、方法和分歧。结合独立的领域框架或额外检索补查资料较少的方向。
4. **用图谱浏览研究进展。** 在「分类与进展」展开或折叠分支，沿着主题和子主题浏览进展。每条里程碑显示在它直接关联的分类下。选择「查看分类证据」可查看该分类及其子类的证据。有时间记录的分支可用「按时间查看」进入对应的时间线，也可以打开「进展时间线」回看全部进展。为可追溯的发现、方法、数据集或评估基准建立里程碑，关联分类及来源文献，并补充原始来源链接。使用成果首次发表、公开或发布的日期，按精度填入年份、年月或完整日期。
5. **制定后续计划。** 把待验证问题写成独立计划，填入相关分类、可交付成果、目标日期和状态，再用「研究计划」跟踪。

工具支持结构化录入、关联和可视化。文献检索、全文解读和分类校对由使用者完成。

## 用综述整理分支演进

仓库内附有 [review-chronology 技能](skills/review-chronology/SKILL.md)，供能够读取文件的 AI 研究助手使用。向助手提供约五篇综述及该技能文件后，可以整理各分支研究什么、如何观测或验证、取得了哪些结果，再生成可通过项目菜单导入的 JSON。

可复制以下指令，并附上自己的综述全文或 PDF。

```text
请阅读 research-atlas/skills/review-chronology/SKILL.md，按其中的工作流处理我提供的约 5 篇综述。
先整合它们的分类，说明各分支研究的问题、对象与尺度。
以原始结果年份按每 3 年分期，比较各分支的机制、方法、成果及有证据的变化幅度。
保留原文章节和原始来源，合并多篇综述引用的同一结果，列出待核实内容。
交付分支演进比较和通过 Research Atlas 数据模型校验的项目 JSON，供我导入。
```

侧边栏的「综述分期」按最早有日期的里程碑年份起算，支持三、四、五年窗口，展示各分支的研究范围和已录入变化。例如首条进展在 2004 年时，三年窗口为 2004–2006、2007–2009，以此类推。录入的时间、比较基准和变化描述决定视图展示的内容。

量化变化需要可比的指标、对象和基准，定性进展可以记录机制、验证范围或研究能力的变化。证据不足时将变化幅度留空，并在备注或计划中记录需补查的内容。内置示例中的综述、成果和幅度均为虚构演示。

## 保存和分享

- 浏览器编辑结果保存在当前浏览器。导出 JSON 可备份、换设备或交给合作者导入。
- 导入或新建项目之前，先导出现有图谱以便继续使用。浏览器清理网站数据也可能清除本地记录。
- 发布工具时，只需分享网页或源码。分享某个研究领域的内容时，同时向读者提供对应的项目 JSON。

## 发布到 GitHub Pages

1. 新建 GitHub 仓库，将此目录内的文件放到仓库根目录，包括 `index.html` 和 `.nojekyll`。
2. 在仓库中打开 **Settings → Pages**。在 **Source** 选择 **Deploy from a branch**，再选择包含这些文件的分支（例如 `main`）和 **/(root)**，然后保存。
3. 发布完成后，在 **Settings → Pages** 通过 **Visit site** 打开网站，再把链接分享给其他人。

参阅 [GitHub Pages 发布源配置](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)和 [GitHub Pages 站点创建指南](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。

## 项目 JSON

导出使用版本 1 的结构，综述与原始研究均存放在 `reviews` 数组里。新增记录时，同一集合中的 ID 应唯一且保持稳定。分类的 `parentId` 留空表示顶级分类，各关系使用对应记录的 ID。文献年份未知时用 `null`。里程碑日期必填，计划日期可以留空，日期格式为 `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`。有效计划状态为 `idea`（构想）、`planned`（已计划）、`active`（进行中）和 `done`（已完成）。

文献与分类之间的映射通过 `section` 记录原文位置，并可填写 `mechanism`（机制）、`observation`（观测方法）、`finding`（研究结果）和 `note`（补充备注）。已有版本 1 的 JSON 可以直接导入。旧映射中的 `note` 会保留，新增字段可在编辑时补充。下方使用虚构数据演示同一分类如何关联一篇综述和一篇原始研究。

里程碑还可填写 `baseline`（比较基准）、`magnitude`（有证据的变化幅度）和 `sourceLocator`（文献与原文位置），类型均为字符串。旧项目缺少这些字段时按空文本处理。日期记录原始结果的年份，具体章节或图表写入 `sourceLocator`。
