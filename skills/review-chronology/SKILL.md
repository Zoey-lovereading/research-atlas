# 从综述建立分支演进图谱

使用用户提供的综述、全文、已有阅读笔记或 Research Atlas 项目，说明各分支研究什么、经历了什么变化，以及证据能支持多大变化。先围绕约五篇互补综述建立框架，再按需要补查原始研究。沿用已有材料、分类和项目 ID。综述数量按实际输入处理。

## 从材料到可追溯证据

1. 先确认研究对象和纳入范围，记录各综述的发表年份、检索截止时间及主题侧重。已有全文就直接读取。只有摘要、章节缺失或扫描不可读时，标记可核实的范围，继续处理可用材料。
2. 按综述的分类、共同问题和实际研究对象整合分支。保留原章节与统一分支的对应关系，合并同义分类。为每个分支写明研究问题、对象与尺度，以及典型观测或验证方法。将尚待补查的方向标出来。
3. 从每篇来源提取具体发现、解释机制、观测或验证方法和研究边界，附原文章节、页码、图表及所引原始论文。区分综述归纳、原始结果和本轮综合判断。对关键年份、比较和量化结果，优先核对原始来源。仅能核实综述转述时写明这一状态。
4. 用原始论文 DOI、题名和相同实验或结果识别重复证据。多篇综述引用同一结果时，建立一条里程碑并汇总来源。相同论文中的独立结果可拆条，注明对应研究、实验或图表。增补材料或更新项目时复用已有结果 ID，并合并新增来源。

综述的范围和检索截止时间决定本轮能覆盖到哪里。通过独立领域框架、原始文献及后续研究检查缺项，记录尚待核实的范围。

## 建立有共同时间基准的分支比较

使用原始结果首次发表或公开的年份给里程碑定年，保留来源提供的日期精度。将综述发表年份放在来源文献记录中。预印本与正式发表对应同一结果时合并记录，说明采用的日期及版本。结果年份无法核实时，保存在分类证据备注或待核实计划中，核实后再加入需日期的里程碑。

默认每三年一个窗口。用户要求四年或五年时使用对应长度，也可按用户要求展示三至五年的对照。各分支共用从项目最早的有日期里程碑年份开始的边界。例如最早为 2004 年时，三年窗口依次为 2004–2006、2007–2009、2010–2012。按里程碑的原始结果年份归入窗口。没有记录的时段标明本轮资料未录入相应进展。

每个分支先说明研究内容，再按时间回答以下问题。

- 该时段针对什么问题、对象和尺度开展研究。
- 使用了什么机制解释、观测或验证方法，增加了哪些可追溯结果。
- 相对于哪个已有结果、方法或能力发生了变化。
- 在可比证据支持下，变化的方向、幅度和适用范围是什么。

比较变化前先核对指标及单位、测量或任务定义、对象与尺度、设计及基准是否匹配。量化幅度保留来源报告的基准、效应或性能变化、单位和不确定性。由同一可比口径的数值计算变化时，写明计算依据，并标为本轮计算。比较百分比与百分点时保留原义。

当进展是引入新机制、扩大验证范围或改变论证能力时，用有出处的定性描述呈现变化。缺少可靠基准或可比证据时，将幅度字段留空，并说明缺什么。论文篇数和结果条数仅描述录入情况。变化幅度依据研究结果本身，避免将文献数量换算为进展程度，也不要生成主观总分。

## 交付 Research Atlas 项目

交付简短的分支演进比较及可导入的 JSON，附待核实事项。用户已有项目时，保留既有记录和计划，合并同义分类及重复结果。用户需要研究计划时写入 `plans`，注明问题、下一步核查和预期交付物。

按下方的版本 1 结构生成 JSON。能访问仓库时，可参阅 [README](../../README.md) 的示例，或在 Node 中设置 `global.window = {}` 后加载 [model.js](../../model.js)，调用 `window.ResearchAtlasModel.validate` 校验。交付前核对字段类型、日期和 ID 引用。

- 顶层保留 `version: 1`、`title`、`description`、`reviews`、`categories`、`mappings`、`milestones`、`plans`。
- `reviews` 同时容纳综述和核实过的原始研究，每项具有 `id`、`title`、`year`、`authors`、`url`、`summary`。未知年份用 `null`。
- `categories` 各项具有 `id`、`name`、`description`、`parentId`。在 `description` 说明该分支研究什么。顶级分类的 `parentId` 为 `""`。
- `mappings` 各项用 `reviewId`、`categoryId`、`section` 关联具体章节，可填 `mechanism`、`observation`、`finding` 和 `note`。同一文献、分类和章节只保留一条映射。
- `milestones` 每项具有 `id`、`title`、`date`、`description`、`categoryIds`、`reviewIds`、`url`，并可填字符串 `baseline`、`magnitude`、`sourceLocator`。在 `description` 写研究新增了什么，`baseline` 写所对照的结果、方法或能力，`magnitude` 写有证据的定量或定性变化，`sourceLocator` 写可核对的文献与原文位置。不同来源的位置分别标注文献题名或 ID。一项结果关联多个分类时复用同一里程碑。
- `plans` 各项具有 `id`、`title`、`date`、`description`、`categoryIds`、`reviewIds`、`status`、`deliverable`。状态用 `idea`、`planned`、`active` 或 `done`。

日期使用 `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`。里程碑日期必填，计划日期可以留空。各引用指向真实存在的 ID，分类父子关系无循环。可选文本缺少证据时用空字符串，链接使用可核实的 HTTP 或 HTTPS 地址。

让用户通过项目菜单导入 JSON，再在「综述分期」选择三、四或五年窗口，查看分支研究范围及已录入变化。仓库内置示例为虚构演示数据，用户自己的图谱应依据所给材料生成。
